## 2. 后端设置与用途

DeepFilterNet3 负责减轻稳定背景底噪。当前路线不再安排 UVR 人声分离；音乐、拍击、摩擦、另一个人声及表演性发声如果无法通过 gate，就隔离/淘汰，不能靠加大降噪强度假定已经解决。干净原音优先，允许整段源文件最终没有合格片段。

在固定版本的 [0.5.6 官方实现](https://github.com/Rikorose/DeepFilterNet/blob/v0.5.6/DeepFilterNet/df/enhance.py) 中，`atten_lim_db` 通过原始频谱与增强频谱混合限制衰减；因此“8 dB”不是每段实际降噪量的承诺。`pad=True` 补偿 STFT/ISTFT 延迟并裁回输入长度；`enhance()` 每次调用会重置模型隐藏状态，不能把反复调用它描述为连续有状态推理。接入方案据此采用有上下文的独立区域处理与接缝验证。

| 设置 | 首版接入安排 | 验收约束 |
| --- | --- | --- |
| 后端与权重 | 沿用 0.5.6 / DeepFilterNet3 / 已有权重 | 锁定配置、权重文件与运行环境；缺失或哈希变化明确报错，不默默切模型 |
| 初始衰减 | 8 dB，复现旧 AB 的保守起点 | 这是试点参数，不是已批准的生产效果；若底噪不足以达标，开发集至多增加一组 12 dB 对照，选定后冻结，不逐片搜索最高 MOS |
| 额外后处理 | `post_filter=false` | 不默认叠加频谱门、强压缩、硬噪声门或多轮降噪，以免吞掉辅音与弱尾音 |
| 延迟补偿 | `compensate_delay=true` | 除样本数一致外，验证局部对齐与长时漂移；不能仅凭总时长相同判定通过 |
| 工作/导出格式 | 48 kHz 浮点分析，最终 48 kHz mono PCM24 | 原始双声道先检测空间风险；重采样记录有理数时间映射，禁止把 16 kHz 检测音频直接充作高频完整的成品 |
| 原音/增强选择 | `raw` 或 `dfn3_denoised`，每个候选只有一个最终版本 | raw 足够干净时选 raw；需要增强的候选必须证明背景改善且人声不受损 |

仅靠低通、高通或升高音量不能使原始削波、近讲/双耳效果、角色音、重叠人声通过。降噪前后均保留这些维度的证据。普通换气保留自然度，明显刻意呼吸/非语言发声按 normal 数据集政策排除。

## 3. 多个长音频的具体处理顺序

1. **源登记与原音预筛。** 分块读取源文件，计算哈希与原始 L/R 特征，运行神经 VAD/粗事件检测；明确音乐、拟音密集、角色或耳语主导的区域先隔离。低能量不能独自证明是底噪，不能误把耳语当作待降噪正常讲话。
2. **生成连续区域。** 初始工程参数为每个核心块最多 30 秒、前后各读取最多 2 秒真实上下文，即单次最多 34 秒。2 秒是待实验验证的预热起点；记录文件首尾缺失的真实上下文，不能用补零伪装成足够上下文。区域与源采样点一一对应。
3. **先检查声道再转换。** 只有原始空间 gate 通过才按已验证规则下混或选声道；规则与声道证据写入清单。首版不独立增强 L/R 后宣称保持了双耳声场，也不把空间风险音频降成 mono 后重新标 normal。
4. **执行一次条件降噪。** 干净区域走 raw。需要降噪且有正常台词潜力的区域使用固定 DFN3 profile。批次加载一次权重；每个独立区域使用明确重置的模型/变换状态，处理上下文后只消费已映射的有效范围，避免前一文件影响后一文件。
5. **生成最终自然句。** 在增强结果上重新做 VAD/ASR 句界并映射回原音，再应用目标身份、normal、事件与文本 gate。首批 3–12 秒候选必须完整落在一个已验收的处理窗口内；跨核心块接缝的句子优先以“完整句 + 真实上下文”另建有界窗口重处理，否则隔离，不能拼接被切开的字。
6. **渲染后再验收。** 复用 LF-11E 的边界渲染；最终 raw/dfn3 成品都重新验证首尾字、齿音、尾音、波形接缝、实际音色及残留事件。淡入淡出不能掩盖截掉音节，也不能作为“没有边界问题”的唯一证据。
7. **只送严格候选。** G0–G8 全部通过、G9 适用域成立的候选再去重和按多样性选择；尚未取得自动认证时小批确认。新 6 源合计最多 24 条、每源最多 6 条；校准样本与正常审核分别标记和计量。

不对整段 30–60 分钟音频调用一次现有 `load_audio/enhance`，也不直接对旧最终短片反复降噪。分块最大长度、上下文长度及接缝保护规则必须版本化，任何调整重新验证依赖产物。

## 4. 生产适配需要补上的契约

- 新增严格校验的 DFN3 生产配置，与 `denoise_ab_v1.yaml` 分开。建议名称为 `deepfilternet3_v2.yaml`，实际创建时固定所有字段；本次不放置会被误认为可运行的空配置。后端参数、声道路由、分块、模型指纹、边界策略、失败行为和输出位置都属于配置身份。
- 原音只读，模型缓存正式运行时优先只读挂载，输出单独可写；保留已有容器环境与缓存，先验证可用性再决定是否需要重建。不更新主 TTS 环境或自动升级 DeepFilterNet。
- 输出建议采用 `data/work/long_form/enhancement/dfn3/<run_hash>/` 与对应版本化报告目录。`run_hash` 绑定源哈希、DFN3 配置、具体权重/环境、区域/声道路由和实现；复用必须验证实际音频哈希。新运行不得写回旧 AB、旧清单或已审核导出。
- 每区域记录 source/core/context 采样范围、真实 padding、重采样映射、声道选择、`raw_sha256`、`denoised_sha256`、延迟检查、处理参数及 `succeeded/failed/interrupted`；写入临时文件后原子提交。重跑只补失败或缺失项，禁止把一条失败扩大成整小时重算。
- 内容筛选另存参考包、gate 配置、校准报告、ASR 与最终成品哈希。调整 gate 阈值可复用同版本降噪缓存；如果改变了区域、声道或增强参数，就必须重新处理相应区域。
- DFN3 失败、输出长度/对齐异常、NaN、缺权重或模型输出为空时，记录原因并阻断该增强候选。不能静默回退 raw 后沿用“已降噪通过”；raw 若独立满足全部条件，可另走有独立证据的原音路线。
- 旧 AB PowerShell 包装器没有生产参数入口，不能只更换默认目录后重跑。新增/扩展入口要显式接收新配置与输出版本，正确传播 Docker build/run 退出码；路径检查须覆盖 inbox、已有输入、历史 AB 和导出目录。

## 5. 有限试点与验收

先做不超过 **12 个原音/DFN3 对照案例**：4 个干净对照、4 个稳定底噪、4 个拍击/音乐/耳语/其他人声等难例，跨源选择。难例的正确结果可能就是 gate 拒绝，不以“所有案例都能降噪保留”为成功目标。原音与增强音算同一个审核案例，复用可用的历史标签和源定位；变化后的成品仍需绑定新证据。

| 检查 | 必须达到的结果 |
| --- | --- |
| 算法/文件 | 48 kHz、预期声道、样本数/时间映射/哈希正确，无非有限值，无意外增益或新增削波 |
| 区域边缘 | 冲激/合成样本检查延迟；真实语音检查窗口中心与接缝附近辅音/尾音；30/60 分钟首中尾局部对齐无未解释漂移 |
| 背景效果 | 稳定噪声样本有可闻改善并满足质量门槛；使用真实非语音上下文估计背景，不用插入的静音制造好分数 |
| 人声保真 | 原音/增强音身份与正常声线稳定、最终文本一致、无吞字；盲听无水声/金属感/空洞，不因单一 cosine 高而放行 |
| 不适合素材 | 拟音、BGM、重叠或非 normal 残留触发相应 gate；未知也不放行；禁止假定 DFN3 能分离角色或去掉全部拟音 |
| 对照公平 | 试听比较避免响度偏好，任何仅用于试听的增益与训练产物分开记录；结果显示真实 raw/dfn3 选择及原因 |
| 恢复与资源 | 区域中断后只补缺失，峰值内存随最大块大小而非总时长增长；记录阶段 RTF、RSS/VRAM、处理覆盖时长和缓存命中 |

试点若 8 dB 对底噪仍不足，在开发集比较一次 12 dB，再选定 profile；若人声保真或事件 gate 仍不过，淘汰该类素材，不能不断增强直到评分过线。试点盲听属于后端接入验收，不代替 LF-12I 的独立联合精度验收，也不自动授权训练。
