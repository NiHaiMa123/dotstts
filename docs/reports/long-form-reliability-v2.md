日期：2026-09-12。对应用户要求：UVR 处理较慢，先修复不依赖 UVR 的问题。

## 已完成的行为

1. 审核导入生成 schema v2 事件，每条绑定源文件、配置、清单及音频哈希。导入前核验实际音频；历史事件与当前清单不匹配时拒绝合并。导出再次检查 v2 决定的绑定。旧日志只有对应原清单的快照才能提供绑定，追加新事件保留历史日志原字节。
2. 精筛列表只保存源区间和特征，不保存 PCM。排序选出首轮候选后逐条重新读取和渲染，包括被排除的候选也不会残留音频数组。
3. ASR 保存 succeeded/partial/failed、成功/失败计数和合并后的时间戳结果。首次调用 ASR 前先提交已生成音频清单；崩溃后复用音频，逐条重试失败、缺失或无有效时间戳的结果。CLI 不对未完成源执行精筛，返回非零状态并列出这些源。
4. pipeline、refinement、review、export 在写入或恢复前校验解析后的输出路径，拒绝与受保护输入重叠。配置相对路径拒绝 Windows 盘符和 UNC 路径。
5. 新运行使用源、配置、实现版本及 ASR 配置文件哈希生成目录标识，保持 `sources/*/*/` 目录层级。强制重跑另建运行；精筛输出标识包含父清单、ASR 结果、精筛配置和实现版本。已完成且内容一致的精筛直接返回缓存，显式指定其他版本目录会报错。
6. 默认精筛配置升级到 `refinement_v2.yaml`：180 ms 上下文、5 ms 零交叉搜索、25 ms 首尾淡化、15 ms 句内连接淡化，保留 80 ms 静音连接。它采用淡化衔接静音的 de-click，不重叠语音内容。处理后的源范围、上下文、淡化长度和输出映射可追溯，导出保留这些记录。
7. 新配置将最短片段统一为 2 秒，精筛及导出检查 2–15 秒。历史 v1 的 1.5 秒配置保持原文件和原哈希；已验收片段不追溯重切。
