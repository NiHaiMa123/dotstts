# ADR 0007: Local review decisions and append-only correction history

- Status: Accepted
- Date: 2026-09-02
- Scope: Slice 7 transcript review, emotion correction, audit history

## Context

Slice 6 froze a 40-item ASR benchmark and routed 31 items to review. The review
workflow must let one local reviewer listen, compare the filename-derived
reference with three frozen ASR runs, correct text and emotion fields, pause and
resume, and retain every prior decision. It must not turn ASR output or an
emotion suggestion into an unreviewed training label.

The corpus currently has no web service or multi-user review system. Adding one
would introduce authentication, deployment and database lifecycle work that is
not justified for 40 benchmark items. A static page is sufficient, provided its
package identity and imported decisions are validated server-side.

## Decision

### Review only the frozen 40-item benchmark first

Slice 7 reviews `fuxuan_asr@2`, with the 31-item queue ordered high, medium and
low, followed by the 9 unflagged items. This validates the workflow on the exact
evidence used to select the ASR backend before extending it to all 277 assets.
The six `难过_sad` items and reference-boundary cases remain mandatory checks.

### Use a generated single-file local page

`review-export` writes:

- `review.html`, a self-contained page whose package data is safely embedded so
  it works when opened through `file://`;
- `review.json`, the canonical package used for hashing and import validation;
- `export.json`, package provenance and counts.

The page stores drafts in localStorage under a key containing benchmark id,
version and the first 16 characters of the package hash. A changed package gets
a separate draft namespace. Invalid or foreign-asset drafts are copied to an
`-invalid-<timestamp>` key and removed from the active key instead of being
silently consumed.

The browser exports a decision JSON file; `review-import` is the only path that
writes canonical decisions. This avoids a local server while retaining a strict
Python validation boundary.

### Store decisions as append-only rounds

Catalog schema v8 stores one `review_decision` row per asset, benchmark version
and review round. A changed mind creates the next round; existing rows are never
updated. Latest-round queries serve downstream slices, while history queries
must explicitly name benchmark id and version.

Round allocation and insertion run in one `BEGIN IMMEDIATE` transaction. This
prevents concurrent importers from choosing the same round and losing a decision
to a uniqueness conflict.

The original `emotion_weak_label` remains in `asr_benchmark_item` and is never
overwritten. Review rows add `emotion_primary`, optional `emotion_secondary`,
optional `intensity`, `label_source`, and `review_status`. `label_source` is
`weak_label_confirmed` unless the reviewer changes or enriches the weak label;
then it is `human_corrected`.

### Make export batches immutable

Every browser export receives a new UUID. Re-importing the exact same file is an
idempotent no-op. Reusing its batch id or row index with different content is a
hard error; it is never treated as `ignored`. Reports are generated by reading
the persisted batch back from the catalog, not by trusting the submitted rows.

### Bind the page to frozen evidence

The review package validates the comparison schema, comparison config and
lexicon hashes, benchmark config and manifest hashes, sample and queue contents,
recommended backend, and every comparison `run_id`. Hypotheses are loaded from
those exact runs rather than whichever run is newest when the page is exported.
All three runs must contain a successful result for every benchmark asset.

Decision import additionally binds to the complete `review.json` SHA-256. It
checks asset membership, exact reference acceptance, allowed emotion values,
UUID and timestamp syntax, defect semantics, and the frozen automatic-rule
payload before opening a write transaction.

### Limit automatic decisions to spelling-invisible homophones

A configured homophone pair may automatically select the frozen reference only
when every available backend difference is fully explained by the pair. The
audio cannot distinguish the intended spelling, so retaining the confirmed
reference is the only reproducible choice.

Missing interjections and reduplication are never automatic. An interjection
hint appears only when every frozen backend starts with an allowed interjection
and the reference starts with none of them. The reviewer must listen before
changing the text.

`flag_defect` is a pending or rejected state, has no final text, and requires a
non-empty note. It cannot be marked approved.

## Alternatives considered

### Update one mutable row per asset

Rejected because it destroys the prior text, label and reasoning whenever a
reviewer changes their mind. Reconstructing audit history from report files
would be fragile.

### Separate text-correction and emotion-correction tables

Deferred. A single decision represents the reviewer's conclusion about one
audio/reference pair and keeps round ordering unambiguous. Separate tables would
allow text and emotion histories to drift independently without a current need.

### Run a local web backend

Rejected for the 40-item phase. It would simplify direct saves but add runtime,
port, shutdown and dependency concerns. The package-hash plus import boundary
provides the needed integrity with fewer moving parts.

### Trust the latest catalog ASR runs

Rejected because the queue and backend recommendation came from a particular
comparison snapshot. Combining those conclusions with later hypotheses creates
an unauditable mixed package.

## Consequences and exit conditions

- The page can pause and resume without a running service and without mixing
  drafts across package revisions.
- All accepted corrections have immutable history and deterministic latest-row
  semantics.
- Browser state remains untrusted; the importer validates all security and
  provenance properties again.
- Review reports may be regenerated from persisted batch rows.
- Slice 7 is complete only after all 40 items receive genuine listening review,
  no unexplained pending items remain (or they are explicitly carried forward),
  the original weak-label fields are unchanged, and the acceptance report records
  test results and artifact hashes.
